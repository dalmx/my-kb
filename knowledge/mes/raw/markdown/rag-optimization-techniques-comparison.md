# RAG 优化技法对照：业界做法 vs 本库实现

## 三、增量点 1：HyDE 假设性文档查询变体（零代码改动）

**原理**（高级RAG技术.md 检索优化第 2 条）：query 与 doc 的 embedding 天然不对称——查询是"问句分布"，文档是"答句分布"。HyDE 让 LLM 先生成一段**假设性答案**，用假设答案（答句分布）去检索，与真实文档的相似度反而更高。

**本库落地方式**：无需改服务端任何代码——`search_knowledge_multi` 的 `queries` 数组本来就走多路 RRF 融合，改写变体时**多生成一路"模拟答案片段"**（100~300 字、含预期表名/控件名/术语的假设回答）塞进数组即可。服务端会照常召回、融合、并用该变体与命中文档配对精排（cross-encoder 对答句-答句对的判分正是 HyDE 的前提）。

**定位**：现有变体（口语/专有名词/同义词）是"问法多样性"，HyDE 补的是"**答案侧多样性**"——专有名词变体都召不回时的兜底一路。

⚠️ **注意**：假设答案可能编造错误术语带偏检索，只作为多路变体之一（不作唯一查询）；融合机制天然容错——错误变体召不回正确文档时不为其加分。触发时机建议放在置信度 ❌ 后的第二次重试，不进默认改写集。

## 四、增量点 2：假设性问答对（写入侧，补 query-doc 不对称）

**原理**（高级RAG技术.md 预检索优化第 3 条）：入库时为每个文档段生成"用户可能会问的问题"，用问句参与索引，检索时变成 query-vs-query 的对称匹配。典型失效场景：正文讲"xx 技术的特点"但全文不出现"优缺点"三字，用户问"优缺点"匹配不上。

**本库现状**：frontmatter tags 含口语同义词是该思想的**弱化版**（标签级、词级，不是句部级）。

**落地方式**：`save_markdown` 时由客户端 AI 生成 3~5 个假设性口语问句，写入正文末尾"## 常见问法"小节，随正文一起被 MarkdownHeader 分块索引。零服务端 LLM，写入规范加一条可选约定即可。

⚠️ **克制使用**：不搞全量补——配合 `get_search_gaps` 的重复≥2 次高频缺口清单，**只对缺口主题文档定向补**。问句占块内 token 且质量依赖 AI，盲目全量会稀释正文语义。

## 五、增量点 3：负样本挖掘（未来微调嵌入/重排模型的前置知识）

**背景衔接**：本库路线图上"精排池 10→30 待数据"；若扩容后 benchmark 提升见顶（如 <2%），下一档优化是**微调 bge 嵌入/重排模型**，而微调检索模型的质量上限取决于难负例（hard negative）构建。

**方法地图**（⑤-20 全文七法）：

| 方法 | 思路 | 风险/要点 |
|------|------|------|
| 随机采样负例 | 均匀抽候选当负例 | 过于简单，分数与梯度趋零，难收敛 |
| Top-K 难负例 | 用检索模型打分，取最高的非正例当负例 | 最常用；易纳入假负例（实则相关的文档） |
| SimANS 困惑负例 | 采样分数介于难/易之间的"不确定区" | 缓解假负例 |
| 对比学习微调构建负例 | 以组间距拉开的对比目标训练 | 常与上述采样法组合 |
| 批内负采样（in-batch） | 同 batch 样本互为负例 | 训练效率高，需大 batch |
| 相同文章采样 | 同文档相邻 chunk 当负例 | 天然难负例，**最贴近本库 markdown 场景** |
| LLM 软标签蒸馏 | LLM 给 query-doc 对打软标签再蒸馏 | 需 LLM，与零服务端架构冲突，暂排除 |

**本库现成资产**：正例对=46 条 benchmark 评测集（query→source 标注）；真实查询分布=gap_log + hit_counts 持续积累；同文章负例=Chroma 内同 source 相邻 chunk 现成可取。触发条件：精排池扩容验证完成且收益见顶后，再评估投入。

## 六、明确不适用的技法（避免重复踩别人的路）

| 技法 | 不适用原因 |
|------|------|
| LLM 提高信息密度/去重/摘要压缩 | 服务端零 LLM；手工 curated markdown 本身信息密度高 |
| 分层索引（摘要索引先行过滤） | 百篇级规模不需要二级索引；标题/h1 规则加权已起类似作用 |
| Self-RAG 完整实现 | 需专用微调模型（selfrag_llama2）；其思想已被置信度分层零成本实现 |
| KG 自动抽取增强 | 已拍板用手工引用图替代（质量高、零抽取成本、无全局摘要需求） |
| 多模态/半结构化 RAG（Multi-Vector Retriever） | 纯 markdown 库，无表格图片解析需求 |
| 提示压缩（LongLLMLingua）/LongContextReorder | 生成侧技法；本库是检索服务不做生成，结果序即消费序 |
| RAGAS/ARES 评测框架 | 评"生成质量"且依赖 LLM 打分；检索侧已有自建 benchmark |
| 备用模型/输出解析/安全护栏 | 全部生成侧痛点，检索服务无此环节 |
